# JobEzz — Master Project Brief (Prompt 0)

> تأكيد المخرجات المطلوبة من PROMPT 0 قبل البناء: التقنية، هندسة المعلومات، وخطة التنفيذ.

## 1) التقنية المُعتمدة (Tech Stack)

| الطبقة | الاختيار | المبرّر |
|---|---|---|
| **العميل (Android + iOS)** | **React Native (Expo)** + TypeScript | أسرع وصول لتطبيق أندرويد نقي مع إعادة استخدام لـ iOS لاحقاً؛ نظام مكوّنات ناضج RTL. |
| **الواجهة والحالة** | React Navigation + Zustand/Context | تنقّل بتبويب سفلي + مكدّس شاشات؛ حالة خفيفة وسهلة. |
| **الواجهة الخلفية** | **Supabase** (Postgres + Auth + Realtime + Storage) | مصادقة OTP بالهاتف، قنوات Realtime للدردشة/الإشعارات/موقع المزوّد، تخزين صور/سير ذاتي/شهادات — بأقل كود خادم. |
| **الخرائط/الموقع** | Mapbox / Google Maps SDK + Supabase Realtime Locations | تتبّع حيّ للمزوّد (Uber-style) ومطابقة حسب القرب. |
| **الدفع** | طبقة دفع **مجرّدة (pluggable)**: كاش افتراضي + تحويل بنكي (إيصال يدوي) + بوابة لاحقة | البنية التحتية للدفع في ليبيا محدودة → التصميم المجرّد يتيح توصيل بوابة دون إعادة هيكلة. |
| **الإشعارات** | Expo Notifications + Supabase Realtime | دفع للتطابقات، تغيّر حالة الطلب، رسائل، إعلانات الدورات. |
| **لوحة الأدمن** | **Next.js (ويب)** بنفس هوية JobEzz | أداة داخلية كثيفة بيانات (تحليلات/مستخدمين/محتوى) — ويب كما ينص Prompt 9. |
| **التصميم** | Figma → نظام تصميم مشترك (الكحلي/الأزرق) | مكوّنات موحّدة بين التطبيق والويب. |

**اللغات:** التطبيق **عربي أولاً RTL** مع مبدّل إنجليزي ثانوي (i18n عبر ملفات ترجمة، وليس نصوصاً مشفرة).

## 2) هندسة المعلومات (Information Architecture) — الملخّص
راجع `02_information_architecture.md` للخرائط التفصيلية لكل دور. الأدوار (حساب واحد متعدد الأدوار):
**باحث عن عمل · صاحب عمل · مزوّد خدمة · عميل · مدرّب · طالب · أدمن.**

التنقّل الرئيسي (تطبيق العميل): `الرئيسية · وظائف · خدمات · دورات · حسابي` + دردشة وإشعارات في الأعلى.
لوحات منفصلة: مزوّد الخدمة، صاحب العمل، المدرّب.

## 3) خطة التنفيذ (Build Plan — مراحل)
- **المرحلة 1 — الأساس:** نظام التصميم + التنقّل + المصادقة (هاتف+OTP) + اختيار الأدوار + الملف + التوثيق. ✅ (منجز في النموذج)
- **المرحلة 2 — الركيزة المميِّزة (الخدمات عند الطلب):** شبكة الفئات → الطلب (وصف/صور/GPS) → مطابقة فورية أو عروض أسعار → تتبّع حيّ → تقييم. ✅
- **المرحلة 3 — لوحة الوظائف:** تصفّح/فلترة/تفاصيل/تقديم + جانب صاحب العمل (نشر/المتقدّمون/الشركة) + تتبّع الطلبات. ✅
- **المرحلة 4 — الأكاديمية:** كتالوج/تفاصيل/تعلّم/اختبار/شهادة + لوحة المدرّب. ✅
- **المرحلة 5 — الدفع/المحفظة:** طرق دفع مجرّدة + عمولة قابلة للإعداد + فواتير + سحب بموافقة. ✅
- **المرحلة 6 — الثقة والدردشة:** دردشة فورية + إشعارات + نظام تقييم موحّد + شارات موثوقية + تبليغ/نزاع. ✅
- **المرحلة 7 — لوحة الأدمن (ويب):** مستخدمون/محتوى/تحليلات/نزاعات/إعدادات. ✅
- **المرحلة 8 — الصقل والإطلاق (P10):** تدقيق RTL/إنجليزي، حالات فارغة/خطأ/تحميل، جولة تفاعلية، وصولية، أصول المتجر، قائمة QA. ✅ (الوثيقة + الحالات موجودة)

> هذا النموذج (HTML/CSS/JS) يُحاكي واجهة تطبيق الأندرويد للعرض والمراجعة، ويُنقل لاحقاً إلى React Native حرفياً بنفس الشاشات والمنطق.
